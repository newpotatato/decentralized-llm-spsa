# Аудит финального simulated run

Дата прогона: 2026-08-21. Аудируемый каталог: `paper_experiment_outputs_objective_full_v3`. Реальные LLM-вызовы не выполнялись.

## Что именно теперь сравнивается

Оптимизаторы оцениваются не по routing score/utility, а по трём сетевым функциям статьи: `Phi_p`, `Phi_w`, `Phi_q`. Primary endpoints — площадь под траекторией каждой функции (`phi_*_auc`, меньше лучше). Для каждого seed все методы получают идентичный exogenous feedback stream в режиме `fixed_replay`; синхронизация фиксирована на `H_sync=5`. Поэтому результат больше не смешивает качество оптимизатора с тем, какие пары выбрал его собственный роутер.

Routing utility сохранён только как диагностическая метрика и не участвует ни в tuning, ни в выборе архитектуры, ни в выводе об оптимизаторах.

## A-SPSA против аналогов

Средние по 10 парным test-seed:

| Метод | Phi_p AUC ↓ | Phi_w AUC ↓ | Phi_q AUC ↓ | Oracle queries |
|---|---:|---:|---:|---:|
| SPSA | 0.675026 | 0.530428 | 0.075274 | 774 |
| A-SPSA | 1.572031 | 0.527171 | 0.103530 | 774 |
| KW | 0.675028 | 0.530052 | 0.075241 | 58,050 |
| ZO-PGD | 0.675027 | 0.530071 | 0.075229 | 774 |
| SP-GT | 0.675025 | 0.539540 | 0.076520 | 387 |
| ZO-GT | 0.675015 | 0.532800 | 0.075879 | 774 |
| PD-2PT | 0.675026 | 0.530071 | 0.075229 | 774 |

Строгий вывод: текущий controlled replay не подтверждает превосходство A-SPSA. Относительно SPSA A-SPSA существенно хуже по `Phi_p` и `Phi_q` (в обоих случаях Holm-adjusted `p=0.0117`), а небольшое улучшение `Phi_w` статистически не подтверждено. Значимое преимущество по `Phi_w` есть только над SP-GT, но оно не компенсирует проигрыш по двум другим независимым целям. Объединять эти три цели в произвольный скаляр постфактум нельзя.

KW достигает примерно того же уровня, что двухточечные методы, ценой 58,050 oracle calls; это важный отрицательный результат по эффективности запросов.

## Абляция

| Вариант | Phi_p AUC ↓ | Phi_w AUC ↓ | Phi_q AUC ↓ | Queries |
|---|---:|---:|---:|---:|
| No learning | 0.185070 | 2.611133 | 0.358668 | 0 |
| Local RLS | 1.936309 | 0.517695 | 0.107916 | 0 |
| SPSA | 0.675026 | 0.530428 | 0.075274 | 774 |
| A-SPSA no momentum | 1.907718 | 0.516465 | 0.106423 | 774 |
| A-SPSA fixed beta | 1.572031 | 0.527155 | 0.103530 | 774 |
| A-SPSA no consensus | 1.612570 | 0.526206 | 0.106149 | 774 |
| Full A-SPSA | 1.572031 | 0.527171 | 0.103530 | 774 |

No-learning неожиданно лучший по processing objective и худший по waiting/quality. Это указывает на сильный исходный processing prior и/или некорректную калибровку обучающего сигнала, а не на «победу отсутствия обучения». Fixed-beta практически совпадает с full A-SPSA: формальная значимость микроскопических парных различий не имеет содержательной важности; поэтому в CSV добавлен отдельный флаг эффекта не менее 1%.

Наиболее вероятные причины слабого A-SPSA здесь:

- processing и quality блоки имеют по 108 параметров при rolling history 100 и разреженной истории каждого агента; задача локально недоопределена;
- у quality loss из статьи нет регуляризатора, поэтому требуемая ускорением сильная выпуклость не гарантирована;
- локальные контроллеры видят разные выборки, и предположение об общем минимизаторе сомнительно;
- online RLS делает целевую поверхность нестационарной;
- feedback остаётся bandit-like: наблюдается только выбранная task-agent пара, exploration пока отключён;
- статья не задаёт `alpha_0`; использовано и записано нейтральное `alpha_0=0`.

Это не ошибка метрики: теперь измеряется ровно функция статьи. Это отрицательный эмпирический результат для данной конечной, частично наблюдаемой и нестационарной постановки.

## Архитектура

Выбрано 3 контроллера, 12 агентов, интервал синхронизации 10. Отбор выполнен на validation без routing utility: constraint `deadline_hit_rate >= 0.80`, затем качество с допуском 0.01 и минимальная инфраструктура. Число агентов находится на верхней границе сетки, поэтому допустима только формулировка «лучший вариант внутри заданного finite budget».

Основные test-результаты при `rho=0.85`:

| Архитектура | Quality ↑ | DHR ↑ | p95 wait ↓ | Throughput ↑ |
|---|---:|---:|---:|---:|
| Legacy local queues | 0.718949 | 0.640000 | 16.7401 | 2.2450 |
| Static skill | 0.717145 | 1.000000 | 0.0000 | 2.5260 |
| Global exact | 0.665387 | 0.999167 | 0.0100 | 2.5158 |
| Centralized exact | 0.685446 | 0.998750 | 0.0000 | 2.5166 |
| Oracle | 0.719489 | 1.000000 | 0.0000 | 2.5342 |

Global buffer устраняет тяжёлое ожидание legacy baseline, но static-skill остаётся сильнее по quality. Он использует заданную симулятором capability matrix, поэтому это информационно сильный baseline. В обычном потоке global greedy и global exact совпадают. В burst stress (`rho=2`, batch=6) exact имеет quality 0.6580 против 0.6535 и p95 wait 10.85 против 13.90 у greedy; статистические выводы следует брать только из Holm-таблицы.

Насыщение действительно наблюдается: при `rho=2.0` utilization 0.9304, DHR 0.8213, p95 wait 12.95 и throughput 4.9208.

## Допустимые claims

Можно утверждать:

- реализовано воспроизводимое раздельное сравнение оптимизаторов по трём сетевым функциям статьи;
- fixed replay устраняет policy-induced feedback confounding в optimizer benchmark;
- архитектурный протокол демонстрирует снижение очередей глобальным буфером в симуляции;
- A-SPSA в текущей постановке не превосходит аналоги и хуже по processing/quality objective.

Нельзя утверждать:

- превосходство A-SPSA в целом;
- превосходство на реальных LLM;
- глобальную оптимальность конфигурации 3/12/10;
- причинное преимущество exact matching без более мощного burst-эксперимента;
- единый «лучший» оптимизатор без заранее заданного правила многокритериального выбора.

## Артефакты и проверки

- `experiment_manifest.json` фиксирует seeds, losses, omega, протоколы и выбранные параметры каждого блока.
- `optimizer_significance.csv` и остальные significance-таблицы содержат Holm-adjusted p-value, средние, относительный эффект и 1% practical-effect flag.
- `optimizers_network_dynamics.png` и `ablation_network_dynamics.png` показывают `Phi` и disagreement по sync-round.
- `optimizer_oracle_efficiency.png` показывает цену результата в objective queries.
- Профильные regression tests и декодирование графиков проверяются перед публикацией.
- Legacy dataset-loader tests могут падать без MBPP/TriviaQA; это отдельная старая ветка данных, не используемая данным six-domain протоколом.
